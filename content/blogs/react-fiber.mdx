## 引言

React 作为当下最流行的前端框架，其内部原理一直为开发者所关注。React 16 引入的 **Fiber 架构** 是一次核心重构，彻底改变了 React 的渲染机制。

## Fiber 是什么

Fiber 是 React 16 引入的核心重构，它重新实现了 React 的调和算法（Reconciliation）。在 Fiber 之前，React 使用 Stack Reconciler，递归处理组件树，一旦开始渲染就必须同步完成，无法中断。

### Fiber 节点的核心结构

```
{
  type: 'div',
  key: null,
  stateNode: DOM节点,
  child: 第一个子节点,
  sibling: 兄弟节点,
  return: 父节点,
  alternate: 双缓冲副本,
  effectTag: 'Update' | 'Placement' | 'Deletion',
  lanes: 优先级标记
}
```

Fiber 架构的核心思想是将渲染工作拆分为可中断的小单元。

## 工作流程

### Render 阶段

Render 阶段是纯计算阶段，可以被中断。React 在此阶段构建一棵新的 Fiber 树：

- **beginWork**: 从根节点开始深度优先遍历，为每个节点创建子节点
- **completeWork**: 从叶子节点回溯，创建真实 DOM 或调用生命周期

### Commit 阶段

Commit 阶段是同步执行的，不可中断，负责将 Render 阶段的变更实际应用到 DOM：

1. **beforeMutation**: 执行 `getSnapshotBeforeUpdate`
2. **mutation**: 实际修改 DOM、新增、删除、更新节点
3. **layout**: 执行 `useLayoutEffect` 和 `componentDidMount/Update`

## 时间切片与优先级

React 利用浏览器的 `requestIdleCallback`（或自实现的 Scheduler）将长任务分割：

```
while (nextUnitOfWork && shouldYield()) {
  nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
}
```

高优先级更新（如用户输入）可以打断低优先级更新（如数据预取），确保 UI 始终流畅响应。

## 总结

Fiber 架构让 React 具备了**可中断渲染**、**优先级调度**和**并发模式**的能力。理解 Fiber 不仅有助于性能优化，更能帮助我们在遇到渲染问题时精准定位根因。
